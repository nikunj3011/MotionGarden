# React exhibition direction

The owner requested web design first, with native carry-over after the React experience is settled. Native source and bundled assets are not updated by the normal web build anymore. `package:native` is an explicit later step.

Reference: https://labs.noomoagency.com/ — inspected for its pale textured environment, large condensed type, centered dimensional subject, sparse navigation and scroll-led motion. MotionGarden uses original typography/layout treatments and its own existing artwork code; no reference artwork, models, textures or branding were copied.

The home route is an exhibition rather than a scrolling card gallery. It uses a rotating transition between artworks, one active renderer and a static departing image, a visible index/counter, category and saved filters, and a dedicated entry link to the full player. Controls remain available without drag or wheel. Reduced motion suppresses spatial animation. The /works route offers a complete title index with thumbnails, creator, rendering medium and category; search covers that metadata and tags, with A–Z/category sorting.

The two current demo packages remain the only advertised works. New packages can appear through the existing catalog. Future iterations can refine the central subject treatment, palettes, animation feel and player controls before porting the native interfaces.

Latest transition treatment: the main renderer uses `surface=transparent` and fills the page behind the exhibition UI. p5 uses destination-out alpha fading for trails, and Three uses an alpha-enabled renderer with transparent clearing. Expanded-player URLs omit this flag and keep opaque themed backgrounds. Outgoing artwork is copied from the actual canvas into a transient canvas; thumbnail artwork is never inserted. The new renderer stays hidden until READY, then materializes through a clipped reveal, depth/blur motion, a grid and a single luminous scan sweep. Only one live renderer is mounted. Reduced motion removes these effects. Tests cover delayed readiness, absence of placeholder image elements, and actual canvas alpha for both artwork engines in both views.

Dark-mode correction: the renderer document explicitly follows the selected browser color-scheme. This prevents a transparent iframe from being composited onto an unintended white browser surface. The dark exhibition uses a quiet near-black violet surface, restrained texture and readable light type without the earlier shadow halo. ART IN sits at the upper left immediately below the introductory line; MOTION stays at the lower right. Custom mode-specific palettes are retained.

Mobile player follow-up: only `/art/:id` gets a non-modal bottom sheet. It starts collapsed and follows pointer dragging from a generous handle, snaps open/closed, supports tapping, Arrow Up/Down and Escape, hides collapsed controls from focus, and scrolls internally when expanded. Portrait and short mobile landscape layouts use the sheet; desktop retains the side panel. The main exhibition controls are unchanged. New seed randomizes all numeric parameters plus a mode-appropriate palette, preserving color count. A saved moment restores both parameters and palette.

Reference-palette follow-up: non-text surfaces now use warm ivory, golden yellow, mist blue and deep blue. Existing text colors, wording and typography are deliberately unchanged. Artwork defaults, add-color suggestions, seed-generated palettes and thumbnails use the same family. Mode-specific palettes now persist under `mg:palettes:v2`; older palettes remain in their previous browser storage key. ART IN / MOTION use staggered blur/mask reveals on transition, and the unchanged artwork details reveal in sequence. Reduced motion disables these effects. A browser test verifies the original text colors and wording in both themes.

Follow-up: artwork is now shown in a wide rounded canvas instead of a circular crop, framed by ART IN above and MOTION below. A Colors panel offers native color inputs, add/remove/reset actions and a gradient preview. A validated SET_PALETTE command carries 1–8 six-digit hex colors; shared runtime interpolation produces a 256-step gradient used by both demo adapters. This is a web/runtime update only; native app source and bundled assets are untouched. Dark and White themes, colors and favorite IDs persist in browser localStorage. Neither a favorite nor the global palette constitutes a cloud-saved artwork variation.
