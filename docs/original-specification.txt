# Generative Art Platform — Full Development Prompt

I'd build this as a premium interactive generative art platform with native Android and iOS apps, a React website, and Cloudflare-hosted artwork packages.

The most important architectural decision: start with Cloudflare R2 + JSON manifests, but design the data layer so you can replace it with ASP.NET Core or FastAPI later without rewriting the apps.

You can also have two experiences:

- Free — Art Explorer: browse, interact with, customize and save generative artworks.
- Pro — Creative Studio: view source code, edit p5.js/Three.js, remix artworks, save code projects and access advanced creator tools.

One important business detail: if a free artwork runs using JavaScript on a user's device, its source code cannot be kept completely secret. You can hide the code editor behind Pro, but someone technically capable can inspect downloaded JavaScript. If protecting proprietary source is essential, you'd need a different delivery model.

For native development, you have two good choices. Since you specifically want native experiences on both platforms, I'd use Kotlin + Jetpack Compose on Android and Swift + SwiftUI on iOS, sharing the TypeScript artwork renderer and JSON contract. This means more platform UI code than Kotlin Multiplatform, but greater independence for native platform features.

If minimizing duplicated mobile code becomes more important, Kotlin Multiplatform with Compose is the alternative.

## 3. Master prompt — copy into your coding agent

# Build FormaFlux — Native Generative Art Platform

You are a principal Android engineer, senior iOS engineer, React architect, graphics programmer, product designer and cloud architect.

Build a production-quality cross-platform generative art platform named **FormaFlux**.

The platform must have three clients:

1. Native Android application using Kotlin, Jetpack Compose and Material 3.
2. Native iOS application using Swift, SwiftUI and modern Apple platform APIs.
3. Responsive React website using TypeScript, Vite and Tailwind CSS.

The platform displays beautiful, interactive, mathematical and procedural artworks created using p5.js, Three.js, GLSL shaders and other compatible browser graphics engines.

The application must look premium, modern, artistic and visually impressive, while remaining smooth, accessible and battery-conscious.

**Critical requirement:** All three clients must use the same artwork packages and JSON data contracts. Do not duplicate artwork rendering algorithms in Kotlin, Swift and React.

Use:

- Cloudflare CDN with a custom domain.

Create a storage abstraction:


Implement the static repository now.

Define interfaces for the future API repository without creating an unnecessary backend.

All clients must support configurable base URLs for development, staging and production.

Add HTTP caching, conditional requests, local artwork caching, retry logic and offline fallback.

Create a Cloudflare publishing CLI that:

## G. Shared rendering engine

Build one reusable artwork runtime in TypeScript.

Supported engines:

1. p5.js for 2D mathematical art and interactive sketches.
2. Three.js for 3D scenes, particles, lighting and procedural geometry.
3. GLSL/WebGL for shader-based effects.

Expose:

```
interface ArtworkEngine {
  initialize(config: ArtworkConfig): Promise<void>;
  setParameters(values: Record<string, unknown>): void;
  resize(width: number, height: number): void;
  pause(): void;
  resume(): void;
  capture(): Promise<Blob>;
  dispose(): void;
}
```

Implement engine-specific adapters.

The native host must send typed messages including INIT, READY, SET_PARAMETERS, RESIZE, PAUSE, RESUME, CAPTURE, ERROR and DISPOSE.

Implement runtime error boundaries, WebGL context-loss recovery, adaptive rendering quality and FPS monitoring.

Do not allow untrusted artwork scripts to access authentication tokens, privileged native APIs or arbitrary external websites.

Use isolated execution contexts, restrictive permissions, navigation restrictions and a carefully audited native bridge.

For monetization, a one-time Pro unlock may be simpler for an initial creative tool. A subscription becomes more justifiable later if you provide ongoing services such as cloud projects, AI generation, collaboration and substantial new content.

With static Cloudflare JSON alone, you can prototype these tiers, but real cross-device subscriptions require secure purchase verification and account/entitlement infrastructure. A small Cloudflare Worker with D1 or another persistent store could be an intermediate step before a full API.

## 6. My recommended first release

Build around these five milestones:

1. Shared renderer: one p5.js artwork and one Three.js artwork running on Android, iOS and React.
2. Cloudflare catalog: JSON-driven artwork discovery, thumbnails, categories and versioned downloads.
3. Premium gallery: native interfaces, fullscreen artwork, parameters and favorites.
4. Creative Studio: source viewer, code editor, local drafts and remixing.
5. Publishing pipeline: validate an artwork, generate a preview and upload it to R2 using a developer CLI.

The biggest advantage of this approach is that you can create one new artwork, upload its package and update the catalog JSON, and it becomes available on all three platforms.

My preferred name is FormaFlux, with AetherCanvas as the alternative if you want a more artistic, less developer-oriented identity. Before committing, check trademarks, app-store names and domain availability.

The one feature I'd prioritize beyond the basic gallery is interactive artwork customization with saved presets. It gives free users something genuinely engaging, makes the gallery more than a collection of videos, and creates a natural path toward the Pro editor.
